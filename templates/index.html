THE CURRENT WORKFLOW

Five steps to deploy

↳ Trigger: push to main
  1. 01

    Check out the code

    GitHub Actions

    The self-hosted runner gets the latest repository files.

    actions/checkout@v4
  2. 02

    Build the image

    Docker

    Docker packages the Flask app and its dependencies into an image.

    docker build -t local-cd-demo:latest .
  3. 03

    Remove the old container

    Replace

    The existing container is removed so the new version can use its name and port.

    docker rm -f local-cd-demo
  4. 04

    Start the new version

    Deploy

    A container runs in the background. Host port 5000 forwards to port 5000 in the container.

    docker run -d --name local-cd-demo --restart unless-stopped -p 5000:5000 local-cd-demo:latest
  5. 05

    Verify the deployment

    Smoke test

    After a short wait, the runner requests the app. A failed request makes the workflow fail.

    curl -f http://localhost:5000
i

What this pipeline does—and doesn’t do

It deploys to the machine running your self-hosted Actions runner. It does not currently run a test suite, publish an image to a registry, deploy to a cloud provider, or roll back automatically if the new container fails. The Actions tab shows the result of each workflow run.
